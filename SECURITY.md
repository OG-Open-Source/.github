# Security Policy

## Maintenance & Support Posture

All repositories in `OG-Open-Source` are maintained on a best-effort, volunteer basis and are provided **"AS IS"** under the [ISC License](https://opensource.org/license/ISC).

- **No SLA or Guaranteed Patch Timeline**: Submitting a security report does not create any legal obligation, warranty, or service-level agreement (SLA) for maintainers to investigate, fix, or release updates within a specific timeframe.
- **Supported Versions**: Unless otherwise noted in a specific repository, only the latest release (or the default branch, if actively maintained) is considered for security fixes. Archived repositories are unmaintained and receive no security updates.
- **No Bug Bounty**: `OG-Open-Source` does not operate a paid bug bounty program.

## Reporting a Vulnerability

**Please do NOT report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, please report suspected vulnerabilities privately using **GitHub Private Vulnerability Reporting** on the affected repository:

1. Navigate to the affected repository's main page on GitHub.
2. Open the **Security** tab.
3. Click **Advisories**, then select **Report a vulnerability** (or click the **Report a vulnerability** button).

### What to Include

To help maintainers triage your report efficiently, please include:

- The affected repository name and version, tag, or commit SHA.
- A clear description of the vulnerability and its potential impact.
- Minimal steps to reproduce or a proof-of-concept (PoC).
- Any suggested remediation or mitigation, if known.

## Coordinated Disclosure & Good-Faith Guidelines

- Please allow maintainers reasonable time to evaluate and respond before publicly disclosing details of a reported issue.
- Please conduct security testing in good faith—do not access, modify, or delete data that does not belong to you, and do not perform denial-of-service testing or social engineering against contributors or maintainers.
